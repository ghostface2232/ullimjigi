# 마법 점검과 비교 (2026-09)

속성별 기본 마법·모아 쏘기·고유 마법·엮기·궁극기를 실제 적 앞에서 쏘아 보며 **예비 동작 → 발사 → 비행 → 적중 → 여운** 다섯 박자, 지속 효과, 타격감, 비용을 점검하고, 분석해 둔 참고작(불·얼음·번개·바람·땅 다섯 속성의 3인칭 마법 액션)과 구조를 비교한 기록입니다. 참고작은 아이디어의 기준점으로만 썼고, 이름·코드·문구는 가져오지 않았습니다. 수치의 원본은 [DESIGN.md](DESIGN.md)입니다.

## 1. 점검 결과 (고치기 전)

| 분류 | 발견 | 조치 |
|---|---|---|
| 성능 · 끊김 | **셰이더 프로그램이 시전마다 다시 컴파일됨.** 룬 원진·구체 오브·회오리·광선·해일 물벽이 시전마다 재질을 새로 만들고 끝나면 dispose해서, 같은 프로그램을 쓰는 재질이 모두 사라지면 three.js가 프로그램을 해제 → 다음 기본 마법 때 재컴파일 (프로그램 수가 131↔134를 오감) | 버리지 않는 견본 재질을 prewarm에서 컴파일해 붙잡음(`VFX._templates`, `keep()`), 해일 물벽은 풀(3개) |
| 성능 · 끊김 | **미리 컴파일이 쓸모없었음.** 부팅 compileAsync와 `VFX.prewarm()`이 캔버스(sRGB) 기준으로 컴파일했지만 장면은 HDR 렌더 타깃(선형)에 그려져서 프로그램 키가 달라 첫 사용 때 전부 다시 컴파일. 쓰이지 않는 프로그램 한 벌이 더 생김 | 컴포저 렌더 타깃을 잡고 컴파일 → 프로그램 **131 → 85개**, 전투 중 재컴파일 0 (첫 사용 컴파일 3~4개만 남음) |
| 깊이 | 지속 효과(불바다·소용돌이·서리 자국)가 **다른 속성과 상호작용하지 않음**. 여운은 연출뿐이라 전장이 전략의 일부가 되지 못함 | 땅의 흔적 시스템(`fields.js`) |
| 깊이 | 반응 대부분이 상태를 **지우기만** 해서 다음 반응으로 이어지지 않음(열충격·과부하·감전 연쇄 뒤 적이 "빈 상태") | 반응이 흔적·상태를 남김 (아래 3절) |
| 깊이 | 기본 마법은 누르고 있으면 연사뿐. 기본 공격 한 칸에 선택지가 없음 | 모아 쏘기 6종 |
| 타격감 | 적중 정지가 `max`로만 쌓여, 틱이 잦은 마법(결정 폭풍 0.14초마다 0.02~0.03초, 소용돌이, 광선)이 게임 시간을 계속 끊어 먹음 | 프레임 합산 + 가벼운 정지 0.3초 제한 (`Combat.stop`) |
| 가독성 | 한기(빙결 전)·젖음·감전 지속에 **몸빛 변화가 없어** 입자 몇 개로만 알 수 있음. 적 상태 표시에 감전 지속·김 없음 | 한기 단계별 푸른빛, 젖음 윤기, 감전 번쩍임, 상태 표시 추가 |
| 균형 | 서리 연사로 영구 빙결 가능 (빙결이 풀리는 순간 다시 한기 3) | 해동 2.5초(보스 5초) |
| 색 | 가산 입자가 밝은 하늘·설원 위에서 색을 잃고 하얗게 뜸 | 가산 입자를 "가산 + 약간의 가림"(premultiplied, 가림 0.3)으로 |
| 정리 | 효과 정리·루프 소리 정지·풀 고갈 문제는 발견되지 않음. 첫 사용 컴파일은 위 항목 외에 화면 굴절 재질·조명 받는 파편·그림자 깊이 재질 정도 | — |

## 2. 참고작과 비교

### 체계

| 항목 | 참고작 | 울림지기 (지금) | 판단 |
|---|---|---|---|
| 한 속성의 칸 | 탭 / 모아 쏘기 / 보조(대개 장판) / 궁극기 + 융합(현재+직전) | 기본 / **모아 쏘기(새로)** / 고유 마법 / 궁극기 + 엮기(현재+직전) | 대등. 고유 마법이 기술로 하나씩 열리는 성장은 우리 쪽이 더 촘촘함 |
| 속성 | 5 (땅 포함) | 6 (물·비전 포함) | 우리: 물이 "적셔서 잇는" 역할, 비전이 "증폭·폭발" 역할 |
| 반응 | 12 | **17** + 연쇄 반응 보너스 + 도감 | 우리가 넓음. 참고작은 반응이 다음 반응의 재료를 남기는 연결이 강했음 → 보강함 |
| 지속 장판과 변형 | 장판이 두 번째 속성을 흡수해 변형(불 회오리, 전기 안개, 흑요석 등) | **땅의 흔적 9종 + 변화 23종(새로)**, 소용돌이 물들이기, 바람 칼날 머금기, 비전 공명 폭발 | 새로 대등 이상. 비전으로 터뜨리기는 우리만의 역할 |
| 상태 이상 | 화상 / 한기→빙결(보스 절반, 빙결 뒤 저항) / 짧은 감전(재발동 제한) / 젖음 / 둔화 / 갑옷 파괴 / 공중 | 화상 / 한기→빙결 / 감전·감전 지속 / 젖음 / 김 / 물방울 감옥 / 갑옷 파괴 / 공중 + **해동(새로)** | 대등 |
| 자원 | 마나: 한동안 안 쓰면 회복이 빨라짐. 기력 | 마나: 반응·처치 방울·완벽 회피로 되찾음, 전투 밖 빠른 회복 | 방향이 다름. 우리는 "섞어 쓰면 버틴다" |
| 타격감 | 반응별 적중 정지·흔들림, 프레임 합산, 화면 펄스 | 반응별 정지·흔들림·FOV·색수차, **합산(새로)** | 대등 |
| 연출 | 침식하는 층진 불꽃, 면 분할 얼음 반짝임, 뜨거운 심의 리본, 속도로 늘어나는 입자, 가산+가림 혼합, 시계방향으로 드러나는 원진, 카메라 쪽으로 띄운 바닥 자국 | 침식 노이즈 구체, 수정 재질, 리본, 속도 늘임 입자, 굴절 패스, 원진, 바닥 자국, **가산+가림(새로)** | 대등. 원진이 그려지며 나타남(새로). 바닥 자국 띄우기는 남은 과제 |
| 환경 | 불→물 위 김, 얼음→물 얼리기, 번개→물 전기, 바람→불 부채질 | 화로·등석·바람개비·얼음 발판 + **`G.env.onSpell` 훅(새로)** | 풀 불·날씨·물 전기는 월드 쪽 작업이 훅을 받아 처리 |

### 속성별

| 속성 | 참고작의 역할 | 우리 역할 (보강 후) | 비고 |
|---|---|---|---|
| 화염 | 지속 피해, 장판(용암), 갑옷 녹이기 | 화상·불길 장판(화염구 잔불, 불씨 폭탄, 과부하), 한기·얼음 녹이기 | 불길은 바람으로 번지고(들불) 번개로 터짐(과열 방전) |
| 서리 | 쌓아서 빙결, 물 얼리기, 얼음 벽 | 한기·빙결·서리밭(서리 창 줄기, 얼음 창), 물웅덩이를 빙판으로 | 해동으로 영구 빙결 방지. 얼음 벽(엄폐)은 없음 |
| 번개 | 순간 경직, 연쇄, 물 전기 | 즉시 적중·연쇄(뇌창 4연쇄)·대전된 땅, 물웅덩이·김을 전류 웅덩이·번개 안개로 | 가장 많은 변화의 "두 번째 속성" |
| 바람 | 띄우기, 퍼뜨리기, 불 부채질, 장판 속성 머금기 | 띄우기·퍼뜨리기(확산 반응), 흔적 부채질·흩뜨리기, **칼날이 흔적 속성을 머금음**, 소용돌이 | 참고작의 좋은 아이디어를 우리 식으로 이식 |
| 물 (참고작엔 없음) | — | 적셔서 번개·서리로 잇기, 웅덩이로 젖음 유지, 불 끄기, 밀쳐 내기 | 우리만의 강점. 소화(역효과)로 조합을 가르침 |
| 땅 (우리엔 없음) | 갑옷·벽·용암·수정 방패 | 역할 일부를 흔적(장판)과 서리·번개의 갑옷 파괴가 나눠 가짐 | 엄폐·벽은 빈자리 |
| 비전 (참고작엔 없음) | — | 공짜 기본 마법, 공명(상태 증폭), **흔적 공명 폭발**, 투사체 지우기 | 흔적을 "터뜨리는" 역할이 새로 생김 |

### 우리가 이미 강한 점 (유지)

- 반응 17종과 반응 도감, 연쇄 반응 보너스, 조화의 나무로 두 속성 섞기를 보상하는 성장 구조.
- 물·비전이라는 참고작에 없는 두 속성의 뚜렷한 역할, 소화 같은 "틀린 조합"도 배움이 되는 설계.
- 속성별로 다른 합성 소리 팔레트(모으기 → 발사 → 마무리 세 박자), 공간 루프 소리, 노이즈 구체·굴절 패스·파편 물리까지 갖춘 다섯 박자 연출.
- 엮기 11종이 각각 모양이 다른 전술(장판, 추적 구름, 광선, 물결, 회오리).

## 4. 성능

같은 자리·같은 카메라에서 적 8마리(체력 무한)에게 고유 마법 5, 엮기 2, 궁극기 6을 연달아 쓰는 약 25초 시나리오(`?dev=skills`).

| 지표 | 이전 | 이후 |
|---|---|---|
| 셰이더 프로그램 수 | 131~146 (전투 중 계속 생성·해제) | 85~86 (전투 중 변화 없음) |
| 갱신(update) 평균 / p95 | 2.9~3.2 / 4.8~5.3 ms | 3.3~4.4 / 5.6~8.6 ms |
| 드로우콜 평균 / 최대 | 590~730 / 760~990 | 660~740 / 900~1100 |
| 입자 평균 / 최대 | 770~1210 / 2050~2560 | 1490~1780 / 3300~3960 |

- 갱신 시간 증가분은 흔적 틱·변화 연출과 늘어난 입자 시뮬레이션이며, 흔적 자체(`Fields.update`)는 초당 1ms 미만입니다.
- 이 시나리오는 모든 적이 죽지 않고 반응이 쉬지 않고 터지는 최악의 경우라 흔적이 계속 12개 가까이 깔립니다. 흔적 연출은 공유 예산(살아 있는 흔적 5개를 넘으면 비례해 줄임, 그래픽 '낮음'에서 절반)과 최대 12개 제한, 열기 아지랑이는 큰 불바다에만(굴절 패스를 계속 켜 두지 않도록) 둡니다.
- 렌더 시간은 같은 기기에서 다른 작업이 GPU를 함께 쓰는 동안 측정해 편차가 너무 커서(같은 장면이 2~30ms) 비교에서 뺐습니다. 사람이 조용한 기기에서 다시 재 보기를 권합니다.
