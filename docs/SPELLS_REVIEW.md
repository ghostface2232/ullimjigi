# 마법 점검과 비교 (2026-09)

속성별 기본 마법·모아 쏘기·고유 마법·엮기·궁극기를 실제 적 앞에서 쏘아 보며 **예비 동작 → 발사 → 비행 → 적중 → 여운** 다섯 박자, 지속 효과, 타격감, 비용을 점검하고, 분석해 둔 참고작(불·얼음·번개·바람·땅 다섯 속성의 3인칭 마법 액션)과 구조를 비교한 기록입니다. 참고작은 아이디어의 기준점으로만 썼고, 이름·코드·문구는 가져오지 않았습니다. 수치의 원본은 [DESIGN.md](DESIGN.md)입니다.

## 1. 점검 결과 (고치기 전)

| 분류 | 발견 | 조치 |
|---|---|---|
| 성능 · 끊김 | **셰이더 프로그램이 시전마다 다시 컴파일됨.** 룬 원진·구체 오브·회오리·광선·해일 물벽이 시전마다 재질을 새로 만들고 끝나면 dispose해서, 같은 프로그램을 쓰는 재질이 모두 사라지면 three.js가 프로그램을 해제 → 다음 기본 마법 때 재컴파일 (프로그램 수가 131↔134를 오감) | 버리지 않는 견본 재질을 prewarm에서 컴파일해 붙잡음(`VFX._templates`, `keep()`), 해일 물벽은 풀(3개) |
| 성능 · 끊김 | **미리 컴파일이 쓸모없었음.** 부팅 compileAsync와 `VFX.prewarm()`이 캔버스(sRGB) 기준으로 컴파일했지만 장면은 HDR 렌더 타깃(선형)에 그려져서 프로그램 키가 달라 첫 사용 때 전부 다시 컴파일. 쓰이지 않는 프로그램 한 벌이 더 생김 | 컴포저 렌더 타깃을 잡고 컴파일 → 프로그램 **131 → 85개**, 전투 중 재컴파일 0 (첫 사용 컴파일 3~4개만 남음) |
| 깊이 | 지속 효과(불바다·소용돌이·서리 자국)가 **다른 속성과 상호작용하지 않음**. 여운은 연출뿐이라 전장이 전략의 일부가 되지 못함 | 땅의 흔적 시스템(`fields.js`) |
| 깊이 | 반응 대부분이 상태를 **지우기만** 해서 다음 반응으로 이어지지 않음(열충격·과부하·감전 연쇄 뒤 적이 "빈 상태") | 반응이 흔적·상태를 남김 (아래 3절) |
| 깊이 | 기본 마법은 누르고 있으면 연사뿐. 기본 공격 한 칸에 선택지가 없음 | 모아 쏘기 6종 |
| 타격감 | 적중 정지가 `max`로만 쌓여, 틱이 잦은 마법(결정 폭풍 0.14초마다 0.02~0.03초, 소용돌이, 광선)이 게임 시간을 계속 끊어 먹음 | 프레임 합산 + 가벼운 정지 0.3초 제한 (`Combat.stop`) |
| 가독성 | 한기(빙결 전)·젖음·감전 지속에 **몸빛 변화가 없어** 입자 몇 개로만 알 수 있음. 적 상태 표시에 감전 지속·김 없음 | 한기 단계별 푸른빛, 젖음 윤기, 감전 번쩍임, 상태 표시 추가 |
| 균형 | 서리 연사로 영구 빙결 가능 (빙결이 풀리는 순간 다시 한기 3) | 해동 2.5초(보스 5초) |
| 색 | 가산 입자가 밝은 하늘·설원 위에서 색을 잃고 하얗게 뜸 | 가산 입자를 "가산 + 약간의 가림"(premultiplied, 가림 0.3)으로 |
| 정리 | 효과 정리·루프 소리 정지·풀 고갈 문제는 발견되지 않음. 첫 사용 컴파일은 위 항목 외에 화면 굴절 재질·조명 받는 파편·그림자 깊이 재질 정도 | — |

| 타격감 | 반응별 적중 정지·흔들림, 프레임 합산, 화면 펄스 | 반응별 정지·흔들림·FOV·색수차, **합산(새로)** | 대등 |

| 환경 | 불→물 위 김, 얼음→물 얼리기, 번개→물 전기, 바람→불 부채질 | 화로·등석·바람개비·얼음 발판 + **`G.env.onSpell` 훅(새로)** | 풀 불·날씨·물 전기는 월드 쪽 작업이 훅을 받아 처리 |

### 우리가 이미 강한 점 (유지)

- 반응 17종과 반응 도감, 연쇄 반응 보너스, 조화의 나무로 두 속성 섞기를 보상하는 성장 구조.
- 물·비전이라는 참고작에 없는 두 속성의 뚜렷한 역할, 소화 같은 "틀린 조합"도 배움이 되는 설계.
- 속성별로 다른 합성 소리 팔레트(모으기 → 발사 → 마무리 세 박자), 공간 루프 소리, 노이즈 구체·굴절 패스·파편 물리까지 갖춘 다섯 박자 연출.
- 엮기 11종이 각각 모양이 다른 전술(장판, 추적 구름, 광선, 물결, 회오리).

## 4. 성능

같은 자리·같은 카메라에서 적 8마리(체력 무한)에게 고유 마법 5, 엮기 2, 궁극기 6을 연달아 쓰는 약 25초 시나리오(`?dev=skills`).

| 지표 | 이전 | 이후 |
|---|---|---|
| 셰이더 프로그램 수 | 131~146 (전투 중 계속 생성·해제) | 85~86 (전투 중 변화 없음) |
| 갱신(update) 평균 / p95 | 2.9~3.2 / 4.8~5.3 ms | 3.3~4.4 / 5.6~8.6 ms |
| 드로우콜 평균 / 최대 | 590~730 / 760~990 | 660~740 / 900~1100 |
| 입자 평균 / 최대 | 770~1210 / 2050~2560 | 1490~1780 / 3300~3960 |

- 갱신 시간 증가분은 흔적 틱·변화 연출과 늘어난 입자 시뮬레이션이며, 흔적 자체(`Fields.update`)는 초당 1ms 미만입니다.
- 이 시나리오는 모든 적이 죽지 않고 반응이 쉬지 않고 터지는 최악의 경우라 흔적이 계속 12개 가까이 깔립니다. 흔적 연출은 공유 예산(살아 있는 흔적 5개를 넘으면 비례해 줄임, 그래픽 '낮음'에서 절반)과 최대 12개 제한, 열기 아지랑이는 큰 불바다에만(굴절 패스를 계속 켜 두지 않도록) 둡니다.
- 렌더 시간은 같은 기기에서 다른 작업이 GPU를 함께 쓰는 동안 측정해 편차가 너무 커서(같은 장면이 2~30ms) 비교에서 뺐습니다. 사람이 조용한 기기에서 다시 재 보기를 권합니다.

## 5. 연출 점검 (2026-11): 모양·박자·시전자

지형·캐릭터·몬스터의 완성도가 올라간 뒤, 마법 연출을 같은 수준으로 맞추기 위한 두 번째 점검입니다. 기준은 최근 액션 RPG의 기술 연출이 공통으로 지키는 **기법**(읽히는 예비 동작, 속성별 모양 언어, 층이 나뉜 적중, 시전자의 연기, 의도가 있는 카메라, 값 관리)이고, 특정 게임의 기술·이름·동작은 참고하지 않았습니다. 방법: 모든 마법을 실제 적 앞에서 60Hz로 한 프레임씩 진행시키며 타임라인을 캡처(낮 13시·밤 23.5시, 52개 시나리오)해 기준선으로 삼고, 프레임을 직접 보며 평가한 뒤 고쳤습니다.

### 5.1 기준선 평가 (고치기 전)

| 항목 | 본 것 | 판정 |
|---|---|---|
| 발사 | 모든 속성의 총구 효과가 지름 1.2~2.4m의 부드러운 가산 발광 + 별 + 원진. 카메라가 5m 뒤라 4~5프레임 동안 시전자의 상체가 빛 덩어리에 묻힘 | 색만 다른 같은 덩어리. 모양 없음 |
| 비행 | 비전·화염·물 기본 마법은 노이즈 구체 + 후광 + 초당 70~90개의 발광 입자 = 빛나는 공. 서리 파편은 세 조각이 후광에 묻혀 흰 덩어리. 바람 칼날만 윤곽이 있음 | 흑백으로 바꾸면 바람 말고는 구별 불가 |
| 적중 | 섬광·고리·구체·불똥이 전부 같은 프레임에 시작해 0.1~0.25초 안에 함께 끝남 | 층은 있으나 박자가 없음 |
| 시전자 | 모든 시전이 같은 자세 반동(`rig.flick()` 기본값) 하나. 효과는 지팡이가 아니라 몸 앞 0.65m의 가상 점에서 나가, 수정과 0.6m 어긋남 | 시전자가 마법을 "쏘고" 있지 않음 |
| 궁극기 | 여섯 속성 모두 같은 시작: 반지름 3~6m의 가산 돔 + 충격 구 + 조명 50이 0.5초 동안 화면을 채움(적중 정지 0.12초가 그 프레임을 붙잡음). 카메라는 FOV −4뿐 | 시전자와 적이 0.5초 동안 보이지 않음. 연출 없음 |
| 낙뢰·천둥 | 번개 줄기의 발광 띠가 줄기 폭의 6배, 기둥 반지름 1.0, 화면 섬광 0.1 | 낮에는 화면의 1/3이 흰색 |
| 화염구 | 비행 중 불덩이가 카메라 앞에서 흰 원반으로 날아감. 폭발 뒤의 불덩이 → 연기는 좋음 | 폭발은 유지, 비행은 재작업 |
| 비전 파동·겨울의 노래 | 시전자 중심의 반지름 6~12m 돔. 카메라가 돔 안이라 0.25초 동안 화면 전체에 무늬 | 화면 가림 |
| 서리 창 | 가시가 발치부터 1.4m로 솟아 1.3초 동안 맞힌 적을 가림 | 모양은 좋음, 시야만 문제 |
| 들불 | 풀밭에서 화염 기본 마법이 맞을 때마다 불이 붙고, 불꽃 카드가 흰색으로 타올라 전투를 덮음 | 불 마법이 자기 여운에 묻힘 |
| 소리 | (들을 수 없음) 속성별 모으기 → 발사 → 마무리 세 박자가 이미 설계돼 있음 | 구조는 유지 |

### 5.2 고친 것

**공통 도구**
- 새 입자 모양 세 가지(같은 셰이더에 추가, 프로그램 수 변화 없음): 15 가는 십자 섬광(`VFX.glint`), 16 얇은 충격 고리(`VFX.puffRing`), 17 일곱 갈래 가시 불꽃(`VFX.pop`). 발사·적중·치명타·폭발의 "번쩍"을 모두 이것으로 바꿔, 면적이 거의 없이 모양으로 읽힙니다.
- 투사체의 몸: 비전은 지팡이 수정과 같은 수정 재질의 **별 바늘**(두 날을 교차시켜 옆에서는 창, 뒤에서는 네 갈래 별), 서리는 각진 조각. 둘 다 풀(pool)에서 꺼내는 불투명 메시라 밝은 하늘·설원 위에서도 값이 유지됩니다(`VFX.body`). 화염·물은 노이즈 구체를 진행 방향으로 늘여 꼬리가 뒤로 흐르는 혜성·물방울(`sphere({ along, squash })`, 새 룩 `comet`·`meteor`).
- 모으기(`VFX.charge`)를 다시 그림: 수정에 맺히는 작은 심 + 조여 드는 얇은 고리 + 중심 앞에서 사라지는 빛 알갱이 + 발밑 원진. 카메라를 보는 큰 원진과 부푸는 발광 구는 없앴습니다.
- 마법이 실제 수정에서 나감(`player.staffTip()` / `gemPos()`).
- 적중(`VFX.impact`)을 박자로 나눔: 0프레임 가시 불꽃·섬광·속성의 몸 → 35~50ms 충격 고리·파편 → 자국과 남는 것.
- 효과 조명·화면 섬광은 낮에 45%(`VFX.lightK`), 번개 발광 띠 6배 → 3.6배.

**속성별**
| 마법 | 바꾼 것 |
|---|---|
| 비전 화살 / 별빛 창 / 별의 노래 | 별 바늘 투사체, 별·글리프 궤적. 궁극기의 별똥별도 큰 별 바늘 |
| 비전 파동 | 돔 → 땅을 따라 낮게 퍼지는 물결 + 바깥으로 던져지는 별 바늘의 관(冠) |
| 불씨 탄 | 검붉은 가장자리의 혜성, 흰빛 아래로 낮춘 불꽃 혀, 그을음, 불똥 |
| 화염구 | 불꽃 모양의 몸 + 어두운 연기 꼬리, 조명 22 → 14, 열 아지랑이 축소 |
| 서리 파편 / 얼음 창 | 더 큰 각진 조각, 터지는 대신 깨지는 적중(불투명 파편 + 찬 김) |
| 서리 창 | 가시가 발치에서 작게 시작해 멀어질수록 커지고, 가까운 것부터 먼저 녹음(판정은 그대로) |
| 낙뢰 / 천둥의 노래 | 가는 잔상 기둥 + 발치의 낮은 폭발 + 가시 불꽃, 줄기 폭 0.5 → 0.4 |
| 돌풍 | 지팡이 앞의 지름 2.8m 원진 제거(초승달 돌풍은 유지) |
| 폭발 공통 | 지름 5~7m 발광 → 가시 불꽃 + 섬광 + 한 박자 늦은 고리, 굴절 껍질은 0.45 → 0.3초 |
| 궁극기 공통 | 0.4초 모으기(굵은 원진이 한 바퀴 그려짐, 빛이 수정으로, 카메라 다가섬) → 0.14초 멈춤 + 화면 띠 → 카메라 반동. 돔·빛기둥 없음. 이름은 화면 왼쪽 아래에 1초 |
| 겨울의 노래 | 한기가 낮게 퍼지고, 얼음은 카메라와 싸움 사이에는 솟지 않음 |
| 치명타 | 금색 큰 별 → 금색 가시 불꽃 + 섬광 + 고리 |
| 엮기 발동 | 지팡이의 큰 별 → 두 속성의 섬광 두 줄 |
| 들불 | 불꽃 카드를 흰빛 아래 주황으로, 가산 → "가산 + 가림", 크기 78%, 낮의 조명 45% (번짐 규칙은 그대로) |

**시전자와 카메라**
- `player.js`가 이제 시전 종류와 속성을 리그에 넘깁니다: `rig.flick(kind, el)`(`bolt`·`charged`·`heavy`·`weave`·`ult`), 모으기 시작 `rig.windup(kind, dur, el)`, 모아 쏘기 진행도 `charge`(0~1), 풀어놓는 순간의 옷·머리 충격 `rig.gust(dir, 세기)`. 뒤의 셋은 리그에 있으면 불립니다(자세는 캐릭터 애니메이션 쪽 작업).
- `CameraRig.focus(dur, { dist, fov, roll, out })`: 조작을 빼앗지 않는 짧은 다가섬. 실제 시간으로 흘러 적중 정지 중에도 이어집니다.

**울림 나무**
- 모든 노드 설명을 "한 줄의 그림 + 정확한 수치"로 다시 썼습니다(수치는 코드와 대조).
- 밋밋한 수치 노드 둘에 3단 효과를 더했습니다: **비전 집중 3**(같은 적을 1.5초 안에 연달아 세 번 맞히면 세 번째에 +0.5P), **충전 3**(이미 감전된 적을 전격으로 맞히면 연쇄 +1).

### 5.4 성능과 셰이더 프로그램

같은 자리(풀밭 50, 122), 같은 카메라, 적 8마리(체력 무한), 들불 꺼 둠. 여섯 속성마다 기본 마법 3 → 모아 쏘기 → 고유 마법, 엮기 5종, 궁극기 6종을 60Hz로 직접 한 프레임씩 진행(2,940프레임)하며 프레임마다 갱신 시간과 렌더 시간(1픽셀 readPixels로 GPU 대기 포함)을 쟀고, 그 순서를 두 번 돌렸습니다. 고치기 전 코드(HEAD)와 고친 코드를 같은 방법으로 쟀습니다.

| 지표 | 이전 (HEAD) | 이후 |
|---|---|---|
| 갱신 평균 / 중앙값 / p95 (ms) | 8.63 / 6.4 / 20.4 | 9.09 / 6.7 / 20.3 |
| 렌더+GPU 평균 / 중앙값 / p95 (ms) | 45.6 / 39.1 / 86.7 | 45.6 / 37.1 / 94.6 |
| 드로우콜 평균 / p95 / 최대 | 1350 / 1602 / 1835 | 1200 / 1416 / 1653 |
| 입자 평균 / p95 / 최대 | 593 / 1034 / 1266 | 625 / 1388 / 1964 |
| 첫 사용 때 새로 컴파일되는 프로그램 | 3개 (원진 2, 양면 노이즈 구체 1) | **0** |
| 시전할 때마다 다시 컴파일되는 프로그램 | 3종 (비전 광선, 폭풍의 눈, 바다의 노래의 회오리) | **0** |
| 프로그램 수 (시전 전 → 전부 시전 후) | 131 → 135 | 140 → 140 |

- 절대값이 문서의 기준(갱신 1.5ms, GPU 4ms)보다 훨씬 큰 것은 헤드리스 Chrome 하나가 다른 작업 넷과 GPU·CPU를 나눠 쓰는 동안 쟀기 때문입니다. 같은 조건의 앞뒤 비교로만 읽어 주세요: 갱신 +5%(평균), 렌더는 오차 범위, 드로우콜 −11%. 입자 최대치는 궁극기 모으기(초당 120개)와 적중 층 때문에 늘었습니다. 조용한 기기에서 사람이 다시 재 보기를 권합니다.
- **재컴파일의 원인과 수정**: 안개·해·그림자·조명 수는 모든 프로그램 키에 들어가는데, `VFX.prewarm()`은 월드가 만들어지기 전(생성 0.8초 뒤)에 한 번만 돌았습니다. 그때 컴파일된 견본(`_templates`: 원진, 양면 구체, 회오리, 광선)은 실제 장면이 요구하는 키와 달라 한 번도 쓰이지 않았고, 원진과 구체는 첫 사용 때, 쓰고 버리는 회오리·광선은 **시전할 때마다** 다시 컴파일됐습니다(1절의 "프로그램 재컴파일 제거"가 월드가 생긴 뒤로는 효과가 없었던 셈입니다). 이제 `VFX.rewarm()`이 플레이가 시작된 뒤 몇 차례(이후 20초마다) 장면의 조명 구성을 확인하고, 바뀌었으면 견본을 다시 컴파일합니다(`compileAsync`, 프레임을 막지 않음). 품질 단계를 바꿔 그림자가 켜지거나 꺼져도 따라갑니다.

### 5.5 아직 기준에 못 미치는 것

- **시전자의 자세**: 종류·속성별 예비 동작과 반동은 캐릭터 애니메이션 작업이 `humanrig.js`에 넣는 중이고, 이 문서의 작업은 호출 시점만 맞췄습니다. 지팡이가 조준선 앞에 오지 않은 프레임에서는 발사 지점이 어깨 앞 가상 점으로 물러납니다.
- **옆·대각선에서 본 모습**: 캡처는 대부분 시전자 뒤에서 조준선을 따라 본 구도입니다. 옆에서 보는 비행 윤곽(혜성의 꼬리, 별 바늘)은 구조상 더 잘 읽히지만 프레임으로 확인한 것은 일부입니다.
- **낮의 번개**: 노란 가산 효과는 햇빛 받은 연두색 풀밭 위에서 값 차이가 작습니다. 조명·섬광을 줄여 화면이 날아가지는 않지만, 낙뢰가 떨어지는 2~3프레임은 여전히 착탄 지점 둘레가 밝게 뜹니다.
- **엮기·반응·흔적**: 공통 도구(발사·적중·폭발·조명)가 바뀌어 함께 정돈됐지만, 11종 엮기와 17종 반응, 9종 흔적을 하나씩 다시 설계하지는 않았습니다. 증기 폭발·끓는 샘의 김 구체, 결정 폭풍의 수정은 여전히 화면을 넓게 차지합니다.
- **궁극기의 몸**: 시작 박자는 새로 만들었지만, 태양의 노래의 착탄(반지름 7m 불덩이가 9m 앞에서 터지면 화면의 절반)과 폭풍의 눈(시전자를 감싸는 회오리)은 크기 자체가 연출이라 그대로입니다.
- **소리**: 이 환경에서는 들을 수 없습니다. 기존의 속성별 모으기(`charge_*`) → 발사(`heavy_*`) → 마무리(`blast_*`, `ult_boom`) 구조를 그대로 쓰고, 궁극기의 모으기 길이(0.4초)를 `ult_cast`의 부풀어 오르는 구간(0.38초 뒤 쿵)에 맞췄으며, 모으는 동안 낮은 `charge_<속성>`, 풀어놓을 때 낮은 `heavy_<속성>`을 겹칩니다. 새 소리 레시피는 만들지 않았습니다. 믹스는 사람이 들어 봐야 합니다.
- **실제 조작감**: 궁극기의 0.4초 지연과 카메라 다가섬이 손에 어떻게 느껴지는지는 사람이 직접 확인해야 합니다.
